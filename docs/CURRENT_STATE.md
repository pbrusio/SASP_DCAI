## 3. Data Pipeline Status

```
Cat9200L → GoFlow2(S2) → Kafka(netflow-raw) → Sanitizer(Mac) → Kafka(netflow-sanitized)
  → Morpheus(S1/CPU) → Triton(netflow-anomaly) → Kafka(morpheus-detections)        [LIVE]

GPU metrics(S1) → abp_detector(S1) → Triton(abp-nvsmi) → Kafka(abp-detections)     [PENDING]
Syslog(S2) → syslog-sanitized → sid_detector(S1) → Triton(sid-minibert)             [PENDING]

ISE generator(Mac) → ise-sanitized → dfp_detector(S1:9097) → Triton(ise-dfp)
  → Kafka(ise-dfp-detections)                                                       [RUNNING]

All detection topics → Bridge(Mac:9093) → LLM Agents(Mac:1234) → Splunk HEC
```

**Key distinction:** Only the NetFlow pipeline has a live data source (Cat9200L switch).
ISE and syslog data are synthetic, generated by `sasp/scripts/testing/ise_auth_generator.py`.
DFP detections in Splunk are real Triton inference results on this synthetic data.

## 4. Known Gaps Requiring Action

See [`KNOWN_GAPS.md`](./KNOWN_GAPS.md) for the full list. Summary:

- **NetFlow autoencoder** needs retraining on real Cat9200L traffic (current weights are uncalibrated)
- **All models** trained on synthetic data — retrain against real telemetry before trusting outputs
- **asset_lookup** and **baseline_query** agent tools are stub implementations
- **ABP and SID detector** daemons on S1 need manual start (scripts ready)
- **All services** run via `nohup` — no systemd persistence across reboots

## 5. How to Bring Up the Environment

Reference [`WAVE4_DEPLOYMENT.md`](./WAVE4_DEPLOYMENT.md) for the full runbook.

Quick reference for services that need manual start after reboot:

```bash
# S2 — Kafka and collectors (usually auto-start, verify with)
ssh <SERVER_USER>@<S2_IP>
systemctl status kafka zookeeper

# S1 — Triton and detectors
ssh <SERVER_USER>@<S1_IP>
docker start sasp-triton sasp-morpheus
./scripts/start_dfp_detector.sh
./scripts/start_abp_detector.sh   # when ready to deploy
./scripts/start_sid_detector.sh   # when ready to deploy

# Mac Studio — Sanitizer, bridges, LLM
./scripts/start_sanitizer.sh
./scripts/start_bridge.sh
./scripts/start_ise_bridge.sh
# LM Studio: open app, verify listening on 0.0.0.0:1234 (not localhost)
```

**LM Studio gotcha:** On Mac reboot, LM Studio resets its listen address to `localhost`. You must manually set it to `0.0.0.0` in LM Studio settings for remote agents to connect.

## 6. What v2 Changes

The v2 roadmap replaces the single ISE DFP autoencoder with a 4-model
ensemble (Isolation Forest + Autoencoder + Prophet + LSTM). See
[`ISE_DFP_ENSEMBLE_ARCHITECTURE.md`](./ISE_DFP_ENSEMBLE_ARCHITECTURE.md)
for the full design.
